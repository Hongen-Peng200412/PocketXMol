## 1. 当前训练配置和执行语义

首轮为 RA/RB × 中心 T0／中心 T1／包络 T0 六个无密度模型，加官方冻结 O 的 C0/C4/E 评价。四个中心模型各评 C0/C4，两个包络模型各评 E，官方评三协议，共 13 个模型×协议、39 个视图汇总。所有比较统一每实例 50 候选、100 步。平移公式、口袋与评价定义以科学契约为准。

### 1.1 用户已经指定的数值

| 参数 | 当前值或行为 |
|---|---|
| 优化器 | 沿用原 AdamW 构造；初始 lr=1e-4，不重写优化器 |
| 其他 AdamW 参数 | 沿用 weight_decay=0.001、betas=(0.99,0.999)、eps=1e-8；不新建旧／新参数学习率分组 |
| warmup | 0 |
| 有效全局批量 | 72；等于每进程 batch × GPU 进程数 × 梯度累积次数 |
| 精度 | 延续 bf16-mixed；真实显存与吞吐待授权 GPU 验收 |
| 单卡起始尝试 | 无密度 batch=36，有密度 batch=24；OOM 可降，并调整累积或获准 GPU 数保持全局 72 |
| 验证 | 每完成 1000 个优化器更新，沿原验证损失路径计算一次 `val/loss` |
| 调度器 | ReduceLROnPlateau，mode=min，threshold_mode=rel，threshold=3e-3 |
| 下降条件 | patience=3，即连续第 4 次未达到相对改善要求时下降；cooldown=0 |
| 下降倍率与下限 | factor=0.2，min_lr=0；沿用默认 eps=1e-8 |
| 停止 | 前两次下降后继续；第三次实际下降触发后立即停止，不再做下一次参数更新 |
| 原损失和置信度 | 全部沿用，包括 `mixed/total` 内的 confidence；不要求不同 microbatch 拆分的归约数值等价 |
| 日志 | 拟用用户 W&B 替代 TensorBoard；运行目录不能依赖某个 logger 的私有目录约定 |

可行分解示例：1 GPU × 36 × 2，1 GPU × 24 × 3，2 GPU × 36 × 1，3 GPU × 24 × 1，均为 72。后两种仅说明算术可行，不代表已授权额外 GPU。验证 batch 可单独按显存配置，不能因 OOM 丢弃验证实例。

典型学习率序列为 `1e-4 → 2e-5 → 4e-6 → 8e-7`，第三个箭头触发停训；不会在 8e-7 再更新参数。这里的改善是相对 scheduler 保存的 best 达到 `current < best × (1−0.003)`，不等同于比上一次验证稍有下降。

### 1.2 最小接线与恢复

现有 `utils/train.py::get_scheduler` 只传 factor、patience、min_lr、cooldown，必须补上 threshold 等必要参数，否则只改配置不会生效。保持原 AdamW 和原验证计算，不建立替代训练框架或额外学习率搜索。

`train_pl.py` 目前直接将 `val_check_interval` 交给 Lightning，它计数训练 batch；累积为 2 或 3 时，不能把“每 1000 个 batch”误写成“每 1000 次参数更新”。实现须按实际优化器更新计数，在边界调用原验证，确保每个验证结果只驱动一次 plateau；不能同时让自动配置和新增回调各 step 一次。所有 rank 使用同一个验证标量、下降次数与停止决定。

第三次下降时先完成该次调度及状态记录，保存停止原因，然后在下一次 optimizer step 之前终止。中断恢复必须保留模型、优化器、scheduler 的 best/坏轮计数、累计下降次数、global_step、RNG、数据状态和已停止标志。已满足正式停止条件的 checkpoint 不得通过普通 resume 清零次数继续训练。Slurm 时间终止、手动中断或 OOM 属于可恢复中断，不叫训练完成。

原 reduced 配置的 180000、作者配套配置的 240000 都只保留为历史参考；新训练不能先被这些旧上限截断。需要用框架支持的无固定步数上限接线，并核验无限训练 Dataset 与原 `max_epochs=1` 不会提前结束，科学停止条件由第三次 plateau 下降控制。

建议六个模型统一加载官方 pxm 的模型参数、建立新优化器并训练全部主干及新增受体参数；O 始终冻结。建议最终使用原 `val/loss` 数值最低的 best，last 用于恢复；scheduler 的显著改善阈值不改变 best 的数值最低定义。这两项建议与实例抽样规则集中保留在最后确认清单，不将未答复项写成已批准。

### 1.3 OOM、验证覆盖与 checkpoint

只读源码发现训练及验证 OOM 路径会调用 `reduce_batch` 丢弃半批实例后继续。这不满足全局批量 72，也会改变验证分母。必要改动是停止静默裁批：出现 OOM 后明确中断，减小单卡 batch、相应调整累积并从完整 checkpoint 恢复；不要伪造少收样本的一次更新。它落实用户已指定的批量，不引入 microbatch 数值等价要求。

原 `utils/dataset.py` 的有限验证迭代器使用 `total_size // total_samplers` 分配每个 worker 的数量，存在尾部遗漏风险。新数据入口要检验每次验证实例的完整覆盖、重复情况、尾批和各 rank 汇总；保持原 loss 定义，不为掩盖遗漏临时更换评价指标。

原 ModelCheckpoint 是 `save_top_k=-1`。不得顺手改成 `save_top_k=1` 自动删除旧 best。建议继续保留定期 checkpoint，用记录标明 best/last，预估并回报存储；仅在用户明确允许时清理具体旧文件。续训不得覆盖另一模型的日志、配置或 checkpoint。

### 2.4 缺失原子的资产已经存在，训练所需图元数据还要补齐

`parse/{pdb_id}/ligand_coords.npz` 中的 `coords_{cid}` 为 `(M,3)`，`present_{cid}` 为长度 M 的布尔数组，均与完整模板原子顺序对齐。缺失位置填 NaN，`centroid_atom_{cid}` 是观测原子质心，单位 Å。

例如实际实例 `("9nvn",0)` 对应 `CCD:LBN`，完整模板 52 个重原子，只有 15 个有沉积坐标。训练使用这 15 个原子的图和坐标；推理使用 52 个原子的完整化学图；评价只比较参考中观测到的原子。

`present` 在训练的数据装配阶段当然用于选择观测原子；“掩码只用于评价”应改成“掩码不传入推理模型作为删原子提示”。否则同一文档会同时要求观测子图训练，又禁止装配时使用存在性信息。

现有 `ligand_objects` 的 `symmetries` 为空，不能直接充当 PocketXMol 的 `matches_iso`。[原图元数据构建代码](../../process/process_torsional_info.py)生成考虑手性的自同构排列，[训练 noiser](../../utils/sample_noise.py)读取它进行原子重分配。因此需要补的是原网络所需的图元数据和索引适配，并非重新生成已有沉积坐标。

部分观测实例还需要明确以下索引处理：完整模板索引映射到观测图的连续索引；训练排列不得引用被删去的原子；评价排列在完整化学图允许的对称关系下选择，再只累积观测原子的误差。不要把所有完整图排列直接套到更短的坐标数组。

缺失导致的断环子图不一定能独立通过通常的化学清理；不能为了构建训练 Tensor 而补坐标、改键型，或默默删除此类样本。以已有完整模板取出需要的原子、键和元数据，并对代表性缺失情形完成开发验收。

### 2.5 受体字段需要显式重编号

完整受体已有 `receptor_tokens.npz`，包含坐标、元素、残基编号和链编号，能够支持从完整受体重新选择口袋。

AdaLigand 蛋白残基顺序为：

`ALA ARG ASN ASP CYS GLN GLU GLY HIS ILE LEU LYS MET PHE PRO SER THR TRP TYR VAL`

PocketXMol [PDBProtein](../../utils/parser.py) 的原顺序为：

`ALA CYS ASP GLU PHE GLY HIS ILE LYS LEU MET ASN PRO GLN ARG SER THR VAL TRP TYR`

不能把 AdaLigand 的 `res_type` 整数直接赋给原网络的 `pocket_atom_to_aa_type`。例如 ARG 在前者为 1，在后者为 14；CYS 在前者为 4，在后者为 1。数据适配应显式按残基名称重编号，并保留原 25 维蛋白特征排列。

模板键类型也不同：AdaLigand 的五列为单、双、三、配位、芳香；PocketXMol 真实键类别为 1、2、3、4，其中 4 表示芳香。因此芳香键是源 one-hot 第 4 列到目标类别 4，不能统一用 `argmax+1`，也不能把配位键误认作芳香键。

核酸标准类别已有 RNA/DNA 编码：20–23 为 A/C/G/U，24–27 为 DA/DC/DG/DT；28 为 UNK，不能直接推断为核酸。已按原子坐标逐项回查实际 UNK 残基的 mmCIF：`9z2n/9z3d/9z2u` 的 `A1CZ2` 是 RNA linking；`9uwi` 的 `A1EQM` 是 D-peptide linking；`9u3a` 的 `LLP` 是 L-peptide linking。三类不能送入同一种新增编码。

583 个候选中，C0 与 E 各有 7 个实例的所选邻域出现标准核酸；各有 1 个没有标准蛋白原子，即 `(9v7o,0,CCD:GMP)`。该 PDB 的完整受体共有 6083 个原子，保存类别全部为 RNA A/C/G/U。C0 有 9 个实例选到 UNK 残基，E 有 5 个；这不是 9/5 个新的核酸实例。C4 的确切邻域要等固定偏移生成后统计，不能从 C0 数字复制。

原 `PDBProtein` 只读 ATOM，过滤非标准氨基酸。继承原蛋白输入时不把修饰蛋白残基强行映射成标准氨基酸，也不因附近有此类残基就删除整个配体实例。已批准的修饰核苷酸保留真实重原子；其碱基母体和修饰字段需要来源支持，不能按编号 28 猜测。

本轮所查 mmCIF 没有直接给出 `mon_nstd_parent_comp_id`，但已继续通过 `_atom_site.label_entity_id/label_seq_id` 对齐 `_entity_poly.pdbx_seq_one_letter_code_can`：`9z2n` 的 entity 2／seq 48、`9z3d` 的 entity 2／seq 3、`9z2u` 的 entity 2／seq 49 均为 canonical C。因此测试中这三处 A1CZ2 已有“修饰 RNA、母体 C”的具体原始记录支持。注意 `9z3d` 的 label seq 3 与 auth seq 34 不同，不能直接以作者残基号索引序列。其余全量修饰残基仍需逐项建立同样可追溯的映射。

### 3.3 free 训练实际使用哪些损失

当前 `ConfTransform` 在 free 训练中设置：`fixed_node=1`、`fixed_halfedge=1`、`fixed_pos=0`、`fixed_halfdist=0`；刚体域和扭转注释是约定形状的空张量。

| 原损失叶 | 参考权重 | 当前 free 训练的掩码含义 |
|---|---:|---|
| node | 1.5 | 没有待恢复原子类别，原实现返回零 |
| pos | 2.5 | 全部观测原子的 XYZ 坐标 MSE |
| edge | 1.5 | 没有待恢复半边类别，原实现返回零 |
| dist | 0.0005 | 无刚体域，当前分支返回零 |
| dih | 0.0005 | 无二面角注释，当前分支返回零 |
| fixed_node | 0.1 | 原子类别固定仍有分类监督 |
| fixed_pos | 0.1 | 没有固定坐标，原实现返回零 |
| fixed_edge | 0.1 | 半边类别固定仍有分类监督，保留原归约 |
| fixed_dist | 0.0005 | 没有固定距离，原实现返回零 |

这张表解释当前数值来源，不授权删除零项或辅助字段。[IndividualTasksLoss](../../models/loss.py)仍按原函数构造、归约并汇总全部叶；总反传键是 `mixed/total`，不能改为 `dock/total`，后者没有包含随后追加的 confidence。

Confidence 的 node／pos／edge 权重为 1／20／1。坐标 confidence 的目标是逐原子 `0.2 ** error_Å`，经 sigmoid 的预测与它计算 MSE；它不是“RMSD < 2 Å 的姿态成功概率”。类别 confidence 使用原 BCE 目标。目标分支 detach，confidence 预测仍通过共享节点／边表示向主干传递梯度，不能误写成只训练置信度头。

原训练重分配使用平均逐原子欧氏距离，不是严格 RMSD。新增平移插在其前面时可能改变所选对称排列。因此“每个原子增加相同平移”的验收应在重分配之前进行，不能要求最终重排后的每行坐标差仍是同一个向量。

### 3.4 两个口袋定义成立，但原点不能混用

[sample_use.py](../../scripts/sample_use.py)把给定中心构造成单原子占位配体，然后调用同一残基选择函数。默认判据都是残基重原子质量中心到参考配体任一原子的严格距离阈值。中心示例为 15 Å，GT 包络预处理为 10 Å；选中残基后保留其原子。

中心示例显式将给定中心用作局部原点。包络 benchmark 默认 [FeaturizePocket](../../utils/transforms.py) 使用所选口袋原子算术均值作为原点。质量中心用于残基筛选，算术均值用于模型原点，这两者也不能混写。

包络密度块围绕 GT 配体中心裁剪，是用户已经确定的条件。但其规则网格的空间位置会表达这个精确中心，而原包络无密度先验不使用该中心。即使数据空间完全对齐，比较也可能包含额外定位信息的收益。

用户在本轮明确：模型坐标系完全按原版对应入口继承，密度裁剪中心使用本轮给定的配体中心，允许该中心带扰动。因此，先前提出的“改用 GT 中心先验”的额外对照撤下，不列入执行安排。

具体对应关系是：中心模型训练及 C4 评价按带偏移的配体中心裁剪，C0 按真实配体中心裁剪；初次包络训练和 E 评价按真实配体中心裁剪。密度体素坐标换算到原网络的坐标系，单次轨迹内裁剪中心固定。后续两阶段的预测中心属于另外的条件构造，尚不在本轮实现范围。

论文和报告应描述实际给定的密度块位置。当前比较检验这一密度条件输入的收益，不额外宣称已经拆开了密度块定位与密度数值各自的贡献。

### 3.5 采样预算与排序要分别固定

[benchmark 配置](../../configs/sample/test/dock_poseboff/base.yml)使用 50 个候选、100 步、种子 10831；[单复合物中心示例](../../configs/sample/examples/dock_smallmol.yml)使用 100 个候选、100 步、种子 2024。用户已确认首轮全部 C0/C4/E 对照采用 50 个候选、100 步。候选数、随机种子和批处理大小是不同字段，不能仅改候选数后把其余混用称为原入口。

[原排序代码](../../scripts/rank_pose.py)同时提供：

- `self_ranking = cfd_traj + no_clashes + stereo`，其中 `cfd_traj` 来自生成模型。
- `tuned_ranking = tuned_cfd + no_clashes + stereo`，其中 `tuned_cfd` 来自独立的作者 ranker。

两个布尔检查通过时各加 1。当前已确定只使用原 `self_ranking`，保留 confidence 训练目标及原轨迹聚合。tuned ranker 虽已定位，当前不加载、不适配、不补跑；它不是默认首选或强制依赖。不同生成模型的 confidence 也不是统一校准的成功概率。

原排序的两个辅助检查不等于完整 PB-valid。当前 vendored `buster_tools` 的距离检查按受体原子的元素、PDB 元数据和排除类型计算，没有标准氨基酸白名单，不能仅凭变量名 `protein` 断言它完全不能处理 RNA；但也不能据此宣布当前 NA 输入和全套 PoseBusters 已验收。特别是 `organic_cofactors` 在有 PDB 元数据时没有自动排除所有 HETATM 的分支，实际送入哪个受体文件会改变检查原子集合。新适配必须显式说明使用完整受体还是蛋白子集。

官方蛋白模型不接新增核酸特征，但纯 RNA 的 `(9v7o,0)` 仍在 C0/C4/E 尝试原正常推理流程并保留分母。原 `FeaturizePocket` 对空蛋白会产生 `(0,3)` 的空 center，错误可能早于 forward；须区分输入构造、模型 forward、采样、坐标还原和评价各阶段，不能把未进入 forward 写成模型 forward 失败。不得为成功运行临时填零点、以 GT 质心替代包络原点或添加假蛋白。记录已知给定中心、实际口袋／原点及真实错误；如果原入口无法到达 forward，按失败记录交付，只有新的明确许可才改官方核心的空输入行为。核酸占比按每协议所选口袋在官方蛋白过滤前统计，包含 100% 情形，保存逐实例结果便于用户以后重算。

## 4. 密度复用与几何实现

### 4.1 直接切 48 个源体素，模型原点不变

现有 `density/{pdb_id}/exp.npy+exp.npz` 与 sim 为 `(1,Z,Y,X)`，`origin` 是世界 XYZ 边界角点。直接使用 AdaLigand 已按 Pocket_Plus 风格重采样的资产，不再执行 MRC origin/start 转换或二次重采样。实际 XYZ spacing 从元数据读取，例如 9lfa 约为 1.000336 Å，9nvn 约为 1.001739 Å，不当作 1 Å 常量。

成熟代码位于 [stage1_requests.py](../../../Pocket_Plus/src/datasets/stage1_requests.py) 的 `resolve_stage1_start` 和 `centered_start_from_centroid_zyx`：前者先 `np.rint`，再将起点裁到 `[0,full_shape−box_shape]`，图小于块时抛出 ValueError。默认块是 80³，本项目明确传入 `(48,48,48)`，不能沿用默认 80。

设请求裁块中心为 $Q$，源角点为 $O$，实际 XYZ spacing 为 $d$，数组形状为 $S_{zyx}$。中心的连续体素中心索引是 $((Q-O)/d-0.5)_{zyx}$；按成熟函数得到：

$$
s_{zyx}=\operatorname{clip}\!\left(\operatorname{rint}\!\left(((Q-O)/d)_{zyx}-24\right),\ 0,\ S_{zyx}-48\right).
$$

先检查任一源维度小于 48 就报错，再按实际起点直接切三个长度 48 的维度。沿用 NumPy rint 的取整，包括半整数行为，不另造 floor/trunc 规则。exp、所用 sim 和当前实例标签必须使用同一源几何与实际切片；不补零、不增加有效体素 mask，归一化用整个裁块。

块内索引 $i$ 和实际起点 $s$ 重排成 XYZ 后，体素中心的模型坐标为：

$$
x_{voxel,model}=O+(s+i+0.5)\odot d-C.
$$

$C$ 是原 PocketXMol 中心化原点：中心模式为本次给定中心，包络模式为选定口袋世界坐标的算术均值。$Q$ 在中心训练/C4 为给定扰动中心，在 C0/E 为观测配体中心。裁块内缩只改变 $s$，不改 $Q$ 或 $C$。公式中的 $s$ 是裁块起点，不是平移机制中同名字母表示的噪声强度。

若沿原数据增强做共同刚体变换，对配体、受体、体素坐标一起应用；保持源密度数组直接切片，不旋转插值重采样它。D2/D4 将当前原子位置通过对应逆变换换回块索引再查询，不能将旋转后的 XYZ 直接索引原数组。裁块起点允许内缩；原子查询越界则取邻域交集或空残差，不夹边伪造信号。

本轮已核对公式、成熟源代码及元数据，未运行新 Dataset、整张密度内容或增强验收。地图任一轴不足 48 是数据错误；预检时记录具体实例并按已批准的少量异常规则处理，不给模型填假块。

### 4.2 “按 Pocket Plus 的 focal＋Dice”可以继续精确化

本地 [stage1_unet_c1.yaml](../../../Pocket_Plus/configs/loss/stage1_unet_c1.yaml)调用 [AdaptiveClassificationCompositeLoss](../../../Pocket_Plus/src/modules/losses.py)：二分类配置实际为两个 logits，经 softmax；`focal_gamma=2`、类别权重 `[0.5,0.5]`、全裁块体素平均，比例为 `w_focal=0.7` 与 `w_tversky=0.3`，MSE 权重为零。

Tversky 的两个误差系数均为 0.5，前景统计在批次和空间维度上汇总，smooth=1。它是 Dice 型重叠损失，但平滑项和归约不能由另一份常见 Dice 实现随意替换。“类别 1:1”在这里表示两类相等，具体数值为 0.5／0.5；换成 1／1 会把 focal 绝对尺度翻倍。

建议 D3 显式采用这个已存在的具体公式，目标改为当前配体实例的区域，不把 Pocket Plus 所有其他任务头和整个 wrapper 引入 PocketXMol。若选择单 logit 的 sigmoid 等价实现，应验证全裁块归约和尺度相同。辅助系数 $\eta_{seg}$ 仍单独在验证阶段确定。

### 4.3 56 通道沿用现有算子

[density_channel_builder.py](../../../Pocket_Plus/src/datasets/density_channel_builder.py)的实际通道顺序为运算外层、归一化中层、后处理内层：

```text
OPS   = [exp, sim, diff, posdiff]
NORMS = [nonorm, clipnorm]
POSTS = [nopost, gauss1, gauss2, DoG1, DoG2, smooth1, smooth2]
```

这形成 4×2×7=56 个通道。`diff=exp-(a*sim+b)`，`posdiff=max(diff,0)`；DoG 的实际符号是 `G(1.6σ)-G(σ)`，不能凭名称反写。高斯使用 reflect 边界；smooth 需要受体掩码，不能当作另一种普通高斯通道。clipnorm 使用 0.001／0.999 分位裁剪后标准化。尺度拟合有受体掩码和高密度筛选，样本不足或 sim 方差不足时回退到 `a=1,b=0`。

当前采用图内完整裁块，不产生零填充区。现有通道函数没有 `valid_mask` 入口正好符合新决定，不补此接口；归一化使用整个裁块。算子自身的受体区域掩码用于差图拟合或 smooth，不是边界有效体素掩码，两者不要混淆。首轮密度仍从 exp 单通道开始，sim、差值和 56 通道不成为无密度首轮前置。

已查 `9lfa` 的 sim 元数据：Chimera 1.19，`strict_hetatm_removed=true`，来源只保留所选模型的 ATOM 重原子。这有助于说明目标小分子未被显式加进模拟受体图，但也会漏掉以 HETATM 保存的修饰聚合物残基；不能把它描述为已经包含新受体定义下的全部核酸／修饰原子。当前只确认此实际元数据样本，未把全数据 sim 重生成作为隐含任务。

### 5.1 直接撤下新增哈希机制

补充前的修改边界文件仅 YAML 模板中就列了 13 个 hash／sha256 字段，另有逐文件 blob 摘要和报告摘要要求。本轮已按此前明确要求将这些模板和要求撤下；它们不进入新正式代码，也不把“能否自动执行”绑定到它们。

| 需要保留的目的 | 足够的保存方式 | 不再增加的机制 |
|---|---|---|
| 说明使用哪份代码 | 可读版本、Git 既有版本标识、运行时源码副本或现有差异记录 | 为每个源码文件再建摘要注册表 |
| 说明使用哪份权重 | 作者发布记录、明确文件路径、对应配置；运行记录引用固定文件 | 每次启动扫描权重计算 SHA |

| 保存结果 | 候选姿态、逐实例指标、汇总与失败原因 | 结果文件摘要不匹配就阻塞其他工作 |

普通文件名、路径和版本标签不提供不可篡改保证；本项目通过保留运行副本和不覆盖已报告结果追溯实验，不声称具备密码学内容证明。

既有资产可能保存历史摘要字段，读取所需科学数组时可以不消费它们。临时检查在 skill 中允许使用哈希，但本轮也没有计算文件哈希；不会把临时校验脚本挂入正式训练入口。

冻结完整实例清单后，以一个固定种子生成每个实例的 C4 向量和采样种子，直接保存数值。之后按 `(pdb_id,candidate_id)` 读取。改变加载顺序、选择 CAP10 或 HF10_TO5 时继续引用同一记录，不重新随机生成。
