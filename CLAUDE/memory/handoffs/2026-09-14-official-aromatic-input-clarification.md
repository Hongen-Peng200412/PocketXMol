# Handoff: 官方芳香键输入核查纠正了此前SMILES阻塞的解释

Date: 2026-09-14

## 当前状态

用户指出应以官方预训练／推理输入为微调参照，而不是要求新SMILES链复现旧ligand_object接入的偏差。只读核查支持这一判断。此前handoff中“必须先接受新的芳香编码才可继续”的解释已被本次证据取代；GPU完整验收与新链集成仍未完成，不能标为预实验通过。

## 已完成的核查

固定官方Git版本65488cf635c856101dbe703ac97e2f10f58e005c的parse_3d_mol从RDKit分子读取键型，将芳香12映射为模型4；官方训练预处理及SMILES推理均使用经过化学检查的分子。旧Dataset直接读取源bonds数组，未使用SanitizeMol后的键，导致28650/66878实例偏离官方表示。

服务器只读CPU检查使用实际提取的官方函数：公共图与官方解析1979个精确SMILES的元素、键端点及类别全部相同，1360个字符串含芳香键。覆盖66878实例，不使用测试坐标、不运行GPU或修改服务器文件。证据tmp/density-preexperiments/official-input-audit-20260914.json。

作者model_weights.tar.gz的pxm/train_config/train.yml第548行为bf16-mixed。官方推理无autocast，使用FP32张量，但导入train_pl会设置medium矩阵乘精度，不能写成严格全FP32。新核查不证明全部旧GPU差异来自键编码；bf16重复波动仍需与迁移错误分开验收。

## 待讨论与下一步

建议采用官方芳香键规则，从规定官方权重初始化；严格等价检查以官方解析为输入参照，并用FP32诊断区分混合精度波动。正式训练建议维持官方bf16混合精度，推理保持官方FP32张量路径。用户询问是否可以全FP32，本轮只说明事实与建议，没有修改精度或提交运行。

历史六模型与官方权重对照都使用旧键编码。必须保留历史结果，但新旧模型差异不能仅归因于密度；是否补做纠正后的无密度RA＋T0及官方对照须由用户决定，不自动新增实验。D1 I/O目标未达到、D4达到，既有三小时预算不自动延长。

本轮仅补充本地日志与本handoff，依项目的讨论文档例外留在Learn/CUMULATIVE工作区，不提交代码、不修改服务器作业。正式实现恢复时保护这些已识别文档更正；原双线端点92d08d6保留。
