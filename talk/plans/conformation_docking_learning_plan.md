# 分子构象生成与小分子对接学习计划

本计划规定 PocketXMol 第一轮学习材料和源码注释的当前目标。完成后，读者应能从二维分子图或蛋白口袋输入出发，沿代码追踪分子构象生成与小分子对接如何构造任务提示、加入坐标噪声、执行几何去噪、重建候选结构并计算评测指标。

## 目标

- 建立 PocketXMol 的统一原子级任务形式化，并集中解释其整体能力来源。
- 分别建立分子构象生成和小分子对接任务档案，区分领域定义、论文 benchmark 和代码实现。
- 建立输入与产物概览、模块结构概览以及指标与排名手册。
- 沿两个任务实际经过的代码路径补充中文学习注释，覆盖模块入口、函数边界、结构化字段、形状、掩码、索引、坐标、GNN、损失、采样和评测。
- 为训练、构象 benchmark、小分子 docking benchmark 和置信度重评估的直接配置补充中文注释，逐项核实字段的消费位置、特殊值、列表顺序和回退关系。
- 保持 Python 可执行语句、YAML 键值、测试、默认参数和产物契约不变；允许的源码差异仅为中文注释与不参与反射的 Docstring，允许的 YAML 差异仅为注释与空白。
- 用按概念依赖排列的本地 Git 提交保存学习顺序，验收后快进 `Learn/CUMULATIVE`。

## 覆盖范围

### 领域与论文

- PocketXMol 的分子表示 $M=(A,X,B)$、蛋白口袋 $K$、任务提示 $P$ 和任务噪声 $\xi$。
- 分子构象生成：给定原子类型和二维化学键，生成一个或多个三维构象。
- 小分子对接：给定刚性蛋白口袋和柔性小分子图，生成小分子在口袋中的三维结合姿态。
- 两项任务的数据来源、测试样本、候选数量、评价指标和排名方式。
- 统一表示、任务提示、联合数据、多类噪声、等变网络、置信度、迭代精修、采样预算与后处理的作用及证据边界。

### 源码

- 正式采样与训练入口中直接装配两个任务的部分。
- 分子、口袋、批次和任务字段的构造与对齐。
- `conf` 与 `dock` 的 transform、noiser 和信息级别调度。
- 当前 PocketXMol 配置实际调用的 embedding、距离特征、分子内消息、口袋条件消息、边更新和坐标更新模块。
- DataLoader 与损失中两个任务实际使用的任务选择、固定掩码、坐标/距离/二面角/置信度计算。
- 采样循环、候选拆分、结构重建、构象评测、对接 RMSD 和候选排序。
- `configs/train/train_pxm_reduced.yml`、两项任务的 benchmark 配置、共用 checkpoint 配置和 docking 置信度配置中由上述代码实际读取的字段。

共享低层模块的注释必须描述其通用输入输出；不能把模块错误描述成只适用于构象或对接。

## 不在本轮范围内

- 线性肽对接、环肽对接和所有肽设计任务。
- SBDD、无条件三维分子生成、分子优化、片段生长、片段连接和 PROTAC 设计。
- 修改模型结构、科学公式、数据字段、默认参数、YAML 键值、测试或输出格式。
- 修复阅读过程中发现的真实缺陷；缺陷只记录证据，另行获得授权后处理。
- 复现论文完整 benchmark 或默认生成 100 个候选的 GPU 运行。

## 执行顺序

1. 冻结 Git 基点、分支和工作区状态。
2. 从任务配置与正式入口确定实际调用路径和数据容器。
3. 沿输入、Dataset、transform、noiser、模型、损失、采样、重建和评测顺序读取源码。
4. 交叉核对论文方法、benchmark 协议、仓库文档和当前实现。
5. 完成六份当前契约文档，并在执行记录中保存发现和证据。
6. 按 `code-comment-style-cn` 为可达源码补充不改变行为的中文注释与 Docstring，并检查关键非标量在首次获得含义或发生重要变化时均有说明。
7. 按 `yaml-config-style-cn` 追到真实消费代码后再注释直接相关配置，不依据键名猜测行为。
8. 先提交本轮 Markdown 文档，再按数据契约、GNN、训练与损失、采样与评测的理解顺序提交源码与配置注释。
9. 检查 Python 可执行语句、YAML 解析值、测试和产物契约未改变，运行相同的轻量验证。
10. 由未参与修改的独立审查者按文件逐项检查范围、正确性和表达规范；返修后重新执行全部验证。
11. 更新映射索引和执行记录，验收后移动 `Learn/conformation-docking` 与 `Learn/CUMULATIVE`。

## 验收标准

- 六份学习文档不依赖隐藏对话即可回答各自负责的问题。
- 输入与产物概览能点名关键字段的形状、语义、单位、对齐关系和生成位置。
- 模块结构概览能沿实际入口定位每个主要模块的输入与输出。
- 两份任务档案能区分任务的一般定义、论文评测协议和 PocketXMol 的具体实现。
- 低层 GNN 注释对其他调用位置仍成立，DataLoader 与损失注释明确两个目标任务使用哪些字段和分支。
- 关键字典、张量、掩码、索引、offsets 与坐标在首次出现或语义变化处具有“形状或形状变化 + 具体实体含义”，模块和边界函数能够独立说明输入、输出和副作用。
- 直接相关 YAML 能说明读取入口、字段类型、作用对象、特殊值和已核实的消费位置；去除注释后与原配置解析为相同值。
- Markdown 数学只使用 MD Human Review 可识别的 `$...$` 与独立 `$$...$$` 定界符，不使用反斜线圆括号或方括号定界符。
- 独立审查者没有遗留高严重度或中严重度问题；所有采纳与不采纳意见均有证据。
- 相对共同基点，允许差异仅为 `.md` 学习文档、中文源码注释和经审查不影响科学行为的 Docstring。
- Python 源码通过语法编译；YAML 解析值和测试内容未改变；可执行语句差异检查未发现变化。
