这是什么意思？详细说明







一句话说，`know_some` 是一种“已知配体部分原子应当位于哪里”的 docking 条件。它不会让整个配体刚性地固定在那里，而是把指定原子当作空间锚点：采样前 80% 阶段精确固定，最后 20% 阶段允许它们在指定半径内自由调整。

## 1. 配置项具体表示什么

示例配置位于 [dock_pep_know_some.yml](C:/Users/15919/Desktop/PocketXMol/configs/sample/examples/dock_pep_know_some.yml:49)：

```yaml
post_process:
  name: know_some
  atom_space:
    - atom: 0
      coord: [-3.522, -13.459, -21.684]
      radius: 2
    - atom: 4
      radius: 2
```

它表达两个独立约束：

- 配体的第 `0` 个原子，应当位于给定坐标附近 2 Å 内。
- 配体的第 `4` 个原子，应当位于输入配体中该原子的原始坐标附近 2 Å 内。

这里的 `atom` 是输入配体中的、从 0 开始的原子索引，不是：

- 元素类型；
- PDB 文件中的 atom serial；
- 整个 batch 拼接后的全局编号。

代码之后会为每个 batch 样本计算全局索引。

## 2. 为什么要减去 `pocket_center`

配置里的：

```yaml
coord: [-3.522, -13.459, -21.684]
```

通常是原始蛋白—配体文件所使用的绝对坐标。

但模型内部不是在这个坐标系里工作。PocketXMol 会把 pocket 平移到局部坐标系：

$$
x_{\mathrm{local}}=x_{\mathrm{world}}-\mathrm{pocket\_center}
$$

所以代码会执行相当于：

```python
coord = coord - batch.pocket_center[i_batch]
```

例如：

$$
c_{\mathrm{world}}=(-3.522,-13.459,-21.684)
$$

如果：

$$
pocket\_center=(-10,-10,-20)
$$

模型实际使用的目标位置就是：

$$
c_{\mathrm{local}}
=(6.478,-3.459,-1.684)
$$

这只是坐标系转换，并没有改变真实空间中的目标位置。

如果没有写 `coord`，则用该原子的 `gt_node_pos`。在这个推理场景中，它通常来自输入配体，并且已经转换到了模型局部坐标系。

## 3. 两阶段机制

100 步采样时，`step` 顺序是：

```text
1.00 → 0.99 → ... → 0.21 → 0.20 → ... → 0.01
```

这里的 `step` 越大，越处于采样早期、噪声越大。分界使用的是原始 `step`，不是经过 `step2level` 映射后的 `level`。

| 阶段 | step | 步数 | 行为 |
|---|---:|---:|---|
| 早期高噪声阶段 | `1.00～0.21` | 80 | 指定原子被精确固定 |
| 晚期低噪声阶段 | `0.20～0.01` | 20 | 解除固定，但检查是否处于半径内 |

也就是：

```text
高噪声：硬锚点                     低噪声：空间容许区域
1.00 ───────────────── 0.21 │ 0.20 ───────────── 0.01
       精确固定                      球内自由，球外拉回中心
```

## 4. 早期为什么叫“精确固定”

在 `step > 0.2` 时，代码大致做三件事。

### 保存原始固定状态

```python
batch.orig_fixed_pos = batch.fixed_pos.clone()
```

因为 `fixed_pos` 后面会被临时修改，所以需要记住原值，以便晚期恢复。

### 临时把指定原子设成 fixed

```python
batch.fixed_pos[atom_index] = 1
```

这不只是普通的标记。`outputs2batch()` 尾部有统一的 fixed 恢复逻辑：

```python
fixed_pos = batch.fixed_pos == 1
pred_pos[fixed_pos] = batch.node_pos[fixed_pos]
```

因此，即使神经网络预测这个原子移动到了别处，预测结果也会被覆盖回已知位置。

假设网络预测：

$$
\hat{x}_0=(5,3,2)
$$

但该原子的已知位置是：

$$
c_0=(1,1,1)
$$

最终写回 batch 的仍然是：

$$
x_0=c_0=(1,1,1)
$$

不是“尽量靠近”，而是完全相等。

### 后续步骤也将它作为已知输入

代码还设置：

```python
self.pre_process = 'fix_some'
```

从下一次采样迭代开始，在模型运行之前，这些原子的输入位置也会恢复为已知位置。

因此早期阶段形成的是完整的硬条件：

1. 输入给模型时，原子在已知位置；
2. `fixed_pos=1` 告诉模型该原子已知；
3. 模型输出后，再次强制恢复到已知位置。

第一次进入 `know_some` 时，模型实际上已经运行过一次，但输出仍会在尾部被覆盖；从第二步开始，模型输入本身也已经受到固定条件约束。

## 5. 没写 `coord` 的第 4 个原子怎么处理

对于：

```yaml
- atom: 4
  radius: 2
```

代码没有外部坐标可写入，于是把输入配体中第 4 个原子的位置作为目标中心。

可以理解为：

```python
coord = batch.gt_node_pos[atom_index]
```

因此：

- `atom: 0` 固定到用户明确给出的空间位置；
- `atom: 4` 固定到输入配体中该原子的参考位置。

这意味着 `know_some` 要求有一个带正确原子顺序的输入配体。尤其是 `atom: 4`，其含义完全依赖输入分子的原子编号。

## 6. 晚期为什么解除固定

到 `step <= 0.2` 时，代码恢复原来的 mask：

```python
batch.fixed_pos = batch.orig_fixed_pos
self.pre_process = None
```

这意味着 `know_some` 临时添加的固定状态消失了。指定原子又可以接受模型预测。

这样做的目的大致是：

- 早期噪声很大，用锚点帮助整个配体找到正确位置和方向；
- 晚期结构已经成形，允许锚点原子做小范围调整，以改善键长、键角、局部构象和 pocket 适配。

但这种自由不是无限制的。每一步模型预测后，代码都会计算：

$$
d=\|\hat{x}-c\|
$$

其中：

- $\hat{x}$：模型对该原子的预测位置；
- $c$：配置坐标或输入配体参考坐标；
- `radius`：允许半径。

然后：

```python
if dist <= radius:
    保留模型预测
else:
    pred_pos[atom_index] = coord
```

以半径 2 Å 为例：

- 距中心 1.4 Å：接受网络预测；
- 距中心恰好 2 Å：接受网络预测；
- 距中心 2.1 Å：直接放回中心；
- 距中心 10 Å：同样直接放回中心。

## 7. 为什么说它不是标准球约束投影

如果一个预测点越出了半径为 $r$ 的球，标准的欧氏投影一般是：

$$
x_{\mathrm{proj}}
=
c+r\frac{x-c}{\|x-c\|}
$$

也就是沿着“中心到预测点”的方向，把点放到球面上。

示例：

- 球心 $c=(0,0,0)$
- 半径 $r=2$
- 模型预测 $x=(3,0,0)$

标准投影得到：

$$
x_{\mathrm{proj}}=(2,0,0)
$$

但这里的实现得到：

$$
x_{\mathrm{result}}=c=(0,0,0)
$$

所以它准确说是：

> 球内不管，球外瞬间吸回球心。

它不是连续的软约束，也不是通常意义上的球面投影。在球面附近会出现明显跳变：

$$
x=(1.999,0,0)\Rightarrow \text{保留}
$$

而：

$$
x=(2.001,0,0)\Rightarrow \text{变成 }(0,0,0)
$$

两次预测只差 0.002 Å，处理结果却可能相差约 2 Å。

## 8. 为什么会扭曲分子结构

代码只修改被指定的单个原子：

```python
pred_pos[atom_index] = coord
```

它不会同步移动：

- 与该原子相连的邻居；
- 所在基团；
- 整个配体。

例如，原本网络预测的一条键为：

$$
\|x_A-x_B\|=1.5\text{ Å}
$$

如果原子 $A$ 被突然吸回到 3 Å 外的球心，而 $B$ 不动，那么键长可能瞬间变成 4 Å。

如果后面还有采样步骤，网络有机会根据新的几何状态重新调整其他原子；但不能保证总能修复。尤其是在最后一步发生吸回时，已经没有下一次网络预测，最终结构可能直接保留这种局部扭曲。

所以它更像一种实用的推理启发式，而不是严格的物理约束或几何优化算法。

## 9. 它约束的不是整个配体

每个 `atom_space` 条目都是独立检查的：

```yaml
atom_space:
  - atom: 0
    ...
  - atom: 4
    ...
```

它只要求：

$$
x_0\in B(c_0,r_0)
$$

以及：

$$
x_4\in B(c_4,r_4)
$$

它不会直接保证：

- 整个配体位于某个区域；
- 两个锚点之间的距离合理；
- 配体保持刚体；
- 手性、键长、键角一定正确。

这些关系主要依靠网络本身重新生成和协调。

## 10. batch 大小假设是什么意思

PyG 会把多个分子的原子拼成一条长数组。例如两个分子各有 10 个原子：

```text
图 0：全局索引 0～9
图 1：全局索引 10～19
```

配置中的 `atom: 4` 是图内局部编号。代码将其换算为：

```python
global_index = atom + num_nodes_per_mol * i_batch
```

于是：

```text
图 0 的 atom 4 → 全局 4
图 1 的 atom 4 → 全局 14
```

但代码通过：

```python
每图原子数 = 总原子数 / 分子数
```

推算 `num_nodes_per_mol`。只有所有图的原子数相同时才正确。

例如 batch 里有：

```text
图 0：20 个原子
图 1：30 个原子
```

代码会推算：

```text
(20 + 30) / 2 = 25
```

于是它认为图 1 从全局索引 25 开始，但图 1 实际从 20 开始，最终约束到错误的原子。

当前示例是同一个配体复制成多个 docking 候选，各候选原子数和顺序完全相同，所以这个假设成立。若混合不同大小的配体，就不可靠；稳健实现应使用每张图的真实起始偏移，例如 `batch.ptr[i_batch]`。

## 总结

`know_some` 的科学含义是：

> 已知若干配体原子的大致空间位置，用这些原子帮助自由 docking 确定配体的位置、方向或局部药效团匹配。

它的实际实现是：

- 前 80 步：把已知原子作为精确的硬锚点；
- 后 20 步：解除硬固定，允许在指定球内调整；
- 越出球体：不是投影到球面，而是直接吸回球心；
- 每个原子独立处理，不保持整个配体的刚性；
- 属于推理阶段的启发式条件控制，不是模型训练得到的严格物理约束。
