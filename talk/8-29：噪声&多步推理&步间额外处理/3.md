一句话概括：这份配置是在做一个“推理期手性/内部几何纠偏实验”。

它表面上仍是 `docking + free`，但在去噪后期的 6 个时间步中，会暂时把“逐原子自由预测”收缩为：

## 1. `correct_pos` 实际做了什么

设：

- `Y = outputs.pred_pos`：网络自由预测的坐标；
- `X_gt = batch.gt_node_pos`：参考构象；
- 配体有 `N` 个原子和 `T` 个可旋转键。

纯 `free` 预测理论上可以在约 `3N` 个坐标自由度上任意移动每个原子。因此网络可能同时预测出：

- 合理的结合位置；
- 合理的大体朝向；
- 但错误的键长、键角、环形；
- 甚至翻转的手性中心。

`correct_pos` 则把可行空间缩小到大约：

- 整体平移：3 个自由度；
- 整体旋转：3 个自由度；
- 可旋转键扭转：`T` 个自由度。

也就是约 `6 + T` 个自由度。

代码执行流程是：

```text
参考构象 X_gt
    ↓
按照网络预测 Y 的二面角，转动允许旋转的单键
    ↓
得到内部几何合法的 X_tor
    ↓
用 Kabsch 求整体旋转 R 和平移 t，使 X_tor 尽量贴近 Y
    ↓
得到修正坐标 X_corrected
```

近似写成：

$$
X_{\text{corrected}}
\approx
T_{\text{rigid}}\bigl(T_{\text{torsion}}(X_{\text{gt}})\bigr)
$$

实际实现位于：

- [correct_pos_batch](C:/Users/15919/Desktop/PocketXMol/models/corrector.py:187)
- [correct_pos](C:/Users/15919/Desktop/PocketXMol/models/corrector.py:246)
- [kabsch_flatten](C:/Users/15919/Desktop/PocketXMol/models/corrector.py:410)

具体分为两步。

### 第一步：从网络预测中提取扭转角

代码分别计算：

```python
sin_in, cos_in = get_dihedral_batch(gt_node_pos, ...)
sin_out, cos_out = get_dihedral_batch(pred_pos, ...)
```

然后得到每条可旋转键需要旋转的角度：

$$
\Delta\theta = \theta_{\text{pred}}-\theta_{\text{gt}}
$$

再把这些扭转施加到 `gt_node_pos` 上。

所以它并不是坚持使用真实构象的可旋转键角度；可旋转键角度主要还是由网络预测决定。

它保留的是参考构象中那些不能通过合法扭转改变的东西，例如：

- 键长；
- 键角；
- 环构象；
- 非旋转键附近的局部几何；
- 立体中心的手性方向。

### 第二步：用 Kabsch 恢复网络预测的 docking pose

扭转完成后，代码用 Kabsch 找到最合适的整体旋转和平移，使修正后的参考构象尽量贴合网络的 `pred_pos`。

因此网络仍然主要决定：

- 配体放在口袋中的位置；
- 配体的整体朝向；
- 可旋转键的大致构象。

参考构象主要负责提供“不应被逐原子自由移动破坏的内部几何”。

所以这里的“投影”是工程意义上的投影，不是严格求解“离 `pred_pos` 最近的流形点”的完整数值优化。

## 2. “通过合法扭转和刚体变换可达到的流形”是什么意思

这里的“流形”可以直接理解为一个合法构象集合：

> 从 `gt_node_pos` 出发，只转动代码标记为可旋转的键，再允许整个配体旋转和平移，所有能够得到的坐标集合。

在这个集合里：

可以变化的：

- 整个配体的位置；
- 整个配体的朝向；
- 可旋转单键的二面角。

不能自由变化的：

- 任意拉长或压缩某根键；
- 任意改变键角；
- 随意扭曲芳香环或刚性环；
- 把手性构象直接镜像翻转；
- 让每个原子各自独立漂移。

例如网络预测得到：

```text
结合位置基本正确
但一个苯环被压扁
某些 C—C 键长度错误
一个手性中心被镜像翻转
```

`correct_pos` 会尝试保留“结合位置、朝向和扭转趋势”，同时把苯环、键长、键角和手性恢复为参考模板允许的几何。

## 3. 为什么 Kabsch 能防止镜像翻转

普通正交对齐既可能产生旋转，也可能产生镜像反射。

代码显式计算：

```python
d = sign(det(U @ Vt))
```

并用 `d` 修正最后一个奇异向量，使最终旋转矩阵满足：

$$
\det(R)=+1
$$

这表示它只能使用真正的三维旋转，不能使用镜像反射。

镜像变换的行列式是 `-1`，会改变手性；正常旋转的行列式是 `+1`，不会改变手性。因此：

- Kabsch 整体对齐不会把参考构象镜像翻转；
- 可旋转键操作本身也是正常三维旋转；
- 从具有正确手性的参考构象出发，通常能保留其手性。

但这不是最终硬约束，因为最后四步又恢复为 free 原始预测。

## 4. 为什么只有 6 步触发

采样步由 [steps_loop](C:/Users/15919/Desktop/PocketXMol/utils/sample_noise.py:480) 产生：

```text
1.00, 0.99, 0.98, ..., 0.02, 0.01
```

配置为：

```yaml
interval_steps: [0.05, 0.1]
```

代码使用闭区间判断：

```python
0.05 <= batch.step <= 0.1
```

所以触发的是：

```text
0.10
0.09
0.08
0.07
0.06
0.05
```

整个时间线是：

- `1.00～0.11`：直接使用 free 网络预测；
- `0.10～0.05`：用参考几何执行 `correct_pos`；
- `0.04～0.01`：重新直接使用 free 网络预测。

每次修正后的坐标都会写入：

```python
batch['node_pos'] = pred_pos.clone()
```

成为下一步采样的当前状态，见 [outputs2batch](C:/Users/15919/Desktop/PocketXMol/utils/sample_noise.py:1007)。

所以后四步虽然不再执行修正，仍然会受到此前修正状态的间接影响；但网络完全可以再次破坏几何或手性。因此它是：

> 晚期轨迹引导，而不是最终结果硬锁定。

## 5. 为什么 `free: 1` 仍然能触发它

这是两套独立机制：

- `settings.free: 1`：决定 docking 的基础运动/噪声模式；
- `post_process: correct_pos`：决定网络预测写回之前是否额外纠正。

正常情况下：

```yaml
settings:
  free: 1
post_process: null
```

才是真正的逐原子自由预测。

当前配置虽然选择 `free`，却又显式指定了：

```yaml
post_process: correct_pos
```

所以在指定时间窗内，后处理分支会覆盖 free 的默认写回行为。

而且推理模式下，即使 setting 是 `free`，代码仍然生成扭转键和刚体域注释，专门供这种几何修正使用，见 [set_torsional_feat](C:/Users/15919/Desktop/PocketXMol/utils/transforms.py:856)。

## 6. `gt_node_pos` 是否构成 oracle 信息

`gt_node_pos` 这个名字并不自动保证它一定是真值；它只是把进入采样变换时的 `node_pos` 复制一份：

```python
data['gt_node_pos'] = data['node_pos'].clone()
```

见 [prepare_sample](C:/Users/15919/Desktop/PocketXMol/utils/transforms.py:825)。

因此关键问题是：

> 复制发生时，`node_pos` 究竟来自哪里？

在这份 [prior_chirality.yml](C:/Users/15919/Desktop/PocketXMol/configs/sample/test/dock_poseboff/prior_chirality.yml:9) 中：

- 数据来自 PoseBusters 测试 LMDB；
- 没有配置 `overwrite_start_pos`；
- `node_pos` 因而来自数据记录中的配体构象；
- 按该 docking 数据管线，它通常就是沉积/参考结合构象。

因此这里很可能使用了评测目标的内部几何。

但要准确区分两件事：

- 它没有把真实结合 pose 整体复制为最终答案；
- Kabsch 会把参考构象重新旋转和平移到网络预测的位置，因此真实的绝对位置和朝向不会被直接保留；
- 它泄露的是目标特有的内部构象几何，尤其是键长、键角、刚性环和手性。

更准确的称呼是：

> 使用目标参考构象几何的 oracle-assisted docking。

而不是：

> 直接把真实 docking pose 复制给模型。

如果比较对象是只获得蛋白口袋、配体化学图或独立生成起始构象的盲 docking 方法，那么这个结果不应与纯盲 docking 直接等价比较。

最终科学判断是：`prior_chirality.yml` 应当看作“参考手性/内部几何先验”的推理消融实验，而不是“只使用高斯噪声的 free docking 主流程”。
